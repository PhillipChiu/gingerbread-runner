# 雲尾衝刺日記

一款以 React、TypeScript、Canvas 與 Vite 製作的繁體中文單頁跑酷遊戲。小跑者會自動向前奔跑；玩家在 20 段逐步加速、障礙變密的原創步道上跳躍、二段跳、滑行並收集能量果實。操作仍只有跳躍與滑行兩種。

## 開始遊玩

需求：Node.js 20 以上、npm。

```bash
npm install
npm run dev
```

開啟終端機顯示的本機網址即可遊玩。遊戲不需要 API、資料庫或後端服務。

### 操作方式

| 動作 | 鍵盤 | 觸控 |
| --- | --- | --- |
| 跳躍／二段跳 | `Space`、`↑` 或 `W` | 點選「跳躍」 |
| 滑行 | 按住 `↓` 或 `S`；也可聚焦滑行按鈕後按住 `Space` / `Enter` | 按住「滑行」，放開即恢復跑步 |
| 暫停／繼續 | `P` 或 `Esc` | 遊戲畫面的「暫停」按鈕 |

第一跳只能在地面開始；角色確實離地後，可在同一次滯空期間再按一次相同的跳躍操作。第三次滯空跳躍無效，真正著地後才會恢復兩次跳躍；按住滑行時不能跳躍。跑道上方的二段跳狀態卡會顯示「可用」、「已用」或「落地恢復」。

L1 先練習基本跳躍；L2 以沒有其他障礙干擾的緊接樹樁教學二段跳，L3–L7 漸進複習，L8 首次介紹需要二段跳的 160px 高樹樁，之後再逐步混合高樹樁、低門與裂隙。障礙提示會配合目前速度與角色的滯空狀態。

桌機可用滑鼠點選 Canvas 下方的「跳躍」與「滑行」大按鈕，也可使用表列鍵盤操作。手機直式畫面把兩個動作放在跑道下方的安全區操作列；手機橫式畫面則將跳躍固定在跑道最左側、滑行固定在最右側，暫停留在上方列，二段跳狀態卡獨立置於跑道上方，不會遮住控制。Canvas 在各種方向都維持 16:7 比例；橫式畫面請以安全區內左右兩側的大按鈕操作。

角色會自動前進。連續低門路段要按住滑行，最後一座通過後放開，再跳過後續樹樁或裂隙；按住期間不能跳躍。收集能量果實以補充體力。單一「體力」資源決定本次奔跑是否結束：體力會隨時間消耗，碰撞會扣減體力，能量果實則可補充體力；歸零時本次奔跑結束。抵達關卡路程目標即可通關並解鎖下一關，也可以重玩已解鎖的關卡。

不同高度的果實需要配合跳躍或滑行收集。可在開始畫面選擇開啟螢幕閱讀器跑道提示；輔助技術會播報關卡開始、前方障礙類型與結算結果，不會逐幀播報 HUD。

### 本 Prototype 的自訂平衡

下列數值是本遊戲自行設定的平衡，**不是官方數值或已確認的官方規則**：初始體力 100 點、每秒消耗 1.2 點、每次碰撞扣 34 點、每顆能量果實補充 18 點；跳躍重力 1,650、第一跳衝量 675、二段跳衝量 470，高樹樁高度／跳躍門檻 160px。各關以距離作為本遊戲自訂通關任務，收集數作為本遊戲自訂紀錄；關卡距離、速度、障礙樣式與分數公式也都是本遊戲自訂設計。

## 專案指令

```bash
npm test        # 執行關卡資料、遊戲狀態與進度儲存測試
npm run build   # TypeScript 檢查並產生 production build
npm run preview # 本機預覽 dist
```

分數、已通關關卡、解鎖進度、最佳分數與收集總數以 `localStorage` 儲存在目前瀏覽器，不會傳送到伺服器。

## GitHub Pages 部署

`.github/workflows/deploy-pages.yml` 會在 `main` 分支更新或手動觸發時執行測試、build，並部署到 GitHub Pages。請在 GitHub repository 的 **Settings → Pages → Build and deployment** 選擇 **GitHub Actions**。

部署建置會將 Vite 的 asset base 設為 `/gingerbread-runner/`，適用於 `gingerbread-runner` repository；一般本機開發與預覽仍使用 `/`。角色圖由 Vite 直接從 repo 根目錄匯入、打包，原始 `main_character.png` 會保留不變。

## 素材與實作

- 遊戲主角使用 repo 提供的 `run_and_slide.png`：上半部 12 格跑步動畫、下半部 12 格滑行動畫。程式先避開標題與編號裁切，再依裁切格外緣取樣棋盤色並 flood-fill 去背，保留米白毛色；跑步與滑行各自對齊錨點並播放循環動畫。舊素材 `main_character.png` 保留於 repo。
- 20 關使用固定距離排程的低門滑行組合、放開距離、後續跳躍與恢復路段；L2 的連跳樹樁與各關高樹樁採用可驗證的提示窗口，路段轉換期間不會隨機插入障礙或能量果實。
- 選單角色預覽會配合系統的「減少動態效果」偏好顯示靜態姿勢；遊戲本身仍可正常操作。
- 場景、障礙、果實與介面以原創 Canvas 繪圖及 CSS 製作；沒有使用官方品牌識別、角色素材或音效。
- 20 關資料集中在 `src/game/levels.ts`；自動移動、解析式跳躍／二段跳、滑行、碰撞、體力與計分邏輯位於 `src/game/engine.ts`。
