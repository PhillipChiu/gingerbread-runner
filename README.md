# 雲尾衝刺日記

一款以 React、TypeScript、Canvas 與 Vite 製作的繁體中文單頁跑酷遊戲。小跑者會自動向前奔跑；玩家在 20 段逐步加速、障礙變密的原創步道上跳躍、二段跳、滑行並收集能量果實。操作仍只有跳躍與滑行兩種，全程搭配一首可隨時關閉的原創背景音樂。

## 開始遊玩

需求：Node.js 20 以上、npm。

```bash
npm install
npm run dev
```

開啟終端機顯示的本機網址即可遊玩。遊戲不需要 API、資料庫或後端服務。

### 操作方式

| 動作 | 鍵盤 | 觸控 |
| --- | --- | --- |
| 跳躍／二段跳 | `Space`、`↑` 或 `W` | 點選「跳躍」 |
| 滑行 | 按住 `↓` 或 `S`；也可聚焦滑行按鈕後按住 `Space` / `Enter` | 按住「滑行」，放開即恢復跑步 |
| 暫停／繼續 | `P` 或 `Esc` | 遊戲畫面的「暫停」按鈕 |

第一跳只能在地面開始；角色確實離地後，可在同一次滯空期間再按一次相同的跳躍操作。第三次滯空跳躍無效，真正著地後才會恢復兩次跳躍；按住滑行時不能跳躍。跑道上方的二段跳狀態卡會依版面顯示「可用」、「已用」或「恢復」；完整標籤會將恢復狀態寫作「落地恢復」。

L1 先練習基本跳躍；L2 以沒有其他障礙干擾的緊接樹樁教學二段跳，L3–L7 漸進複習，L8 首次介紹需要二段跳的 160px 高樹樁，之後再逐步混合高樹樁、低門與裂隙。障礙提示會配合目前速度與角色的滯空狀態。

桌機可用滑鼠點選 Canvas 下方的「跳躍」與「滑行」大按鈕，也可使用表列鍵盤操作。手機直式畫面把兩個動作放在跑道下方的安全區操作列；手機橫式畫面則將跳躍固定在跑道最左側、滑行固定在最右側，暫停留在上方列，二段跳狀態卡獨立置於跑道上方，不會遮住控制。Canvas 在各種方向都維持 16:7 比例；橫式畫面請以安全區內左右兩側的大按鈕操作。

角色會自動前進。連續低門路段要按住滑行，最後一座通過後放開，再跳過後續樹樁或裂隙；按住期間不能跳躍。低門高 144px，滑行仍是主要通過方式；一般單跳最高約 138px 越不過去，只有二段跳在與低門水平重疊的整段期間都高於 144px 才能跳過，高度不足或剛好等於 144px 仍會碰撞。收集能量果實以補充體力。單一「體力」資源決定本次奔跑是否結束：體力會隨時間消耗，碰撞會扣減體力，能量果實則可補充體力；歸零時本次奔跑結束。抵達關卡路程目標即可通關並解鎖下一關，也可以重玩已解鎖的關卡。

不同高度的果實需要配合跳躍或滑行收集。可在開始畫面選擇開啟螢幕閱讀器跑道提示；輔助技術會播報關卡開始、前方障礙類型與結算結果，不會逐幀播報 HUD。

### 背景音樂

20 關共用同一首原創背景音樂 `public/audio/runner-theme-loop.wav`：純器樂、沒有人聲或人聲取樣，也沒有依關卡切換的歌曲或重複的音檔。曲風貼近遊戲溫暖明亮的手繪童話氛圍——96 BPM、C 大調，和弦進行為 Cadd9 – Am7 – Fmaj7 – G7sus4，以柔和的撥奏鈴琴為主旋律，搭配溫暖的 pad、低音與輕柔的節拍。

- **檔案格式**：WAV（無壓縮 PCM）、16-bit、44.1 kHz、立體聲，長度剛好 30.0 秒（1,323,000 個取樣畫格），檔案大小 5,292,044 bytes（約 5.3 MB）。頭尾以 150 ms 交叉淡化後重新取樣為整 30 秒；循環接縫處的取樣跳變遠小於曲內一般的起伏，並由測試把關。
- **播放時機**：預設開啟，音量 0.35，整首循環播放。為符合瀏覽器的自動播放限制，載入頁面時**不會**自動播放；只有玩家按下「開始第 NN 關」（或在開始畫面按 `Enter` / `Space`）、「重新開始本關」、「下一關」、「再跑一次」或「重新挑戰」時，才會在該次操作中開始播放。
- **暫停與繼續**：暫停、回到旅程地圖、出現結算視窗，或分頁切到背景時，音樂會暫停；按「繼續奔跑」會從暫停處接續。重新開始或進入另一關時，音樂從頭開始。
- **單一音訊物件**：整個頁面只建立一個 `HTMLAudioElement`，音源只設定一次；換關與重新開始都沿用同一個物件並回到開頭，不會重新載入。若玩家一開始就把音樂關閉，則不會建立音訊物件，也不會下載音檔。
- **聲音開關**：開始畫面的操作區（「開始第 NN 關」按鈕旁）、遊戲畫面上方列（手機窄螢幕只顯示喇叭圖示）、暫停與結算視窗都有「背景音樂」按鈕。它是原生按鈕，可用 `Tab` 與 `Enter` / `Space` 操作，以 `aria-label="背景音樂"` 命名、用 `aria-pressed` 回報開啟或關閉，點擊區至少 48px，且不會疊在跳躍與滑行按鈕上。選擇會存入 `localStorage`（`cloudtail-runner.background-music.v1`），重新整理、換關與重新開始後仍沿用；若瀏覽器封鎖儲存空間，則只在目前頁面維持。
- **播放失敗提示**：瀏覽器阻擋播放，或音檔載入失敗時，遊戲畫面上方會以 `role="status"` 顯示對應原因與「重試播放」按鈕；遊戲本身仍可靜音繼續。
- **iOS Safari**：iOS 不允許網頁調整媒體音量，實際音量以裝置音量為準。

### 本 Prototype 的自訂平衡

下列數值是本遊戲自行設定的平衡，**不是官方數值或已確認的官方規則**：初始體力 100 點、每秒消耗 1.2 點、每次碰撞扣 34 點、每顆能量果實補充 18 點；跳躍重力 1,650、第一跳衝量 675、二段跳衝量 500，高樹樁高度／跳躍門檻 160px，低門高度／跳躍門檻 144px。各關以距離作為本遊戲自訂通關任務，收集數作為本遊戲自訂紀錄；關卡距離、速度、障礙樣式與分數公式也都是本遊戲自訂設計。

## 專案指令

```bash
npm test        # 執行關卡資料、遊戲狀態、進度儲存與背景音樂（WAV 規格、循環接縫、播放生命週期）測試
npm run build   # TypeScript 檢查並產生 production build
npm run preview # 本機預覽 dist
```

分數、已通關關卡、解鎖進度、最佳分數與收集總數，以及背景音樂的開關，都以 `localStorage` 儲存在目前瀏覽器，不會傳送到伺服器。

## GitHub Pages 部署

`.github/workflows/deploy-pages.yml` 會在 `main` 分支更新或手動觸發時執行測試、build，並部署到 GitHub Pages。請在 GitHub repository 的 **Settings → Pages → Build and deployment** 選擇 **GitHub Actions**。

部署建置會將 Vite 的 asset base 設為 `/gingerbread-runner/`，適用於 `gingerbread-runner` repository；一般本機開發與預覽仍使用 `/`。角色圖由 Vite 直接從 repo 根目錄匯入、打包，原始 `main_character.png` 會保留不變。背景音樂放在 `public/audio/`，程式以 `import.meta.env.BASE_URL` 接上 `audio/runner-theme-loop.wav` 組出網址：部署後是 `/gingerbread-runner/audio/runner-theme-loop.wav`，本機是 `/audio/runner-theme-loop.wav`，不會出現重複斜線，也不需要額外設定。

## 素材與實作

- 遊戲主角使用 repo 提供的 `run_and_slide.png`：上半部 12 格跑步動畫、下半部 12 格滑行動畫。程式先避開標題與編號裁切，再依裁切格外緣取樣棋盤色並 flood-fill 去背，保留米白毛色；跑步與滑行各自對齊錨點並播放循環動畫。舊素材 `main_character.png` 保留於 repo。
- 20 關使用固定距離排程的低門滑行組合、放開距離、後續跳躍與恢復路段；L2 的連跳樹樁與各關高樹樁採用可驗證的提示窗口，路段轉換期間不會隨機插入障礙或能量果實。
- 選單角色預覽會配合系統的「減少動態效果」偏好顯示靜態姿勢；遊戲本身仍可正常操作。
- 場景、障礙、果實與介面以原創 Canvas 繪圖及 CSS 製作；沒有使用官方品牌識別或角色素材。背景音樂是原創的程式合成純器樂，沒有人聲或人聲取樣。
- 20 關資料集中在 `src/game/levels.ts`；自動移動、解析式跳躍／二段跳、滑行、碰撞、體力與計分邏輯位於 `src/game/engine.ts`。
- 背景音樂的播放控制位於 `src/game/backgroundMusic.ts`（單一 `HTMLAudioElement`、靜音偏好與播放失敗狀態，不依賴 React，可直接以假的音訊物件測試）；`src/game/useBackgroundMusic.ts` 把它接到遊戲畫面狀態，開關按鈕與失敗提示則是 `src/components/SoundToggle.tsx` 與 `SoundNotice.tsx`。
